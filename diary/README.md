# 日々の余白｜日別ファイル方式のGitHub Pages日記

記事を**1日1ファイル**として `posts/YYYY-MM-DD.json` に保存し，公開用 `index.html` が `data/index.json`（見出し・日付・タグのみ）を読み込み，表示する日記を必要な分だけ取得する設計です．記事本文は一覧データに入れません．

## ページ

- **`editor.html`：編集**　日付・タイトル・本文を入力し，写真をドラッグ＆ドロップで追加．未公開の下書きと写真はその端末のブラウザ（IndexedDB）に保存します．
- **`preview.html`：公開前テスト**　同じブラウザ内の下書きを，公開サイトと同じデザインで表示します．
- **`index.html`：公開ページ**　GitHubにコミットされた記事だけを表示します．下書きの保存領域にはアクセスしません．

## ファイル構造

```text
diary/
├── index.html               公開用トップ
├── preview.html             下書きのプレビュー
├── editor.html              編集・公開管理
├── data/
│   └── index.json           公開済みの記事リスト（軽量）
├── posts/
│   ├── 2026-11-21.json      2026年11月21日の本文と写真参照
│   └── 2026-11-22.json      2026年11月22日の本文と写真参照
├── images/                  写真本体（例：images/<id>/<photo-id>.webp）
└── assets/
    ├── style.css
    ├── storage.js
    ├── site.js
    └── editor.js
```

最初の配布ファイルは記事0件です．上の `posts/` 内の記事は構造を説明する例で，ZIPには含まれません．

## 記事の追加・更新

1. GitHubリポジトリの所定のフォルダに，このZIPを展開した**中身**をアップロードしてください．ZIPをそのままGitHubに置いてもHTMLから参照されません．
2. GitHub **Settings → Pages** で `main` ブランチなどを公開元に設定します．`diary/` に配置した例：`https://<ユーザー名>.github.io/diary/editor.html`，`preview.html`，`index.html`．
3. `editor.html` で日付・本文と写真を入力します．数秒以内に下書きが自動保存されます．
4. **公開時の見え方を確認**でプレビューします．
5. GitHubへ直接公開，または公開用ZIPを書き出して該当ファイルを手動コミットします．

### GitHubへ直接公開する場合

GitHubアカウント名・リポジトリ名・ブランチ・設置フォルダを入力し，対象リポジトリに限定した Fine-grained Personal Access Token（**Contents: Read and write**）を**公開時だけ**入力してください．GitHub APIを使い，**記事の日付JSON，軽量な記事一覧，追加した写真**を同じコミットで更新します．公開済みの日記の編集にも対応しています．記事の日付変更では旧日付ファイルを同じコミットで削除します．GitHubでの競合があれば公開に失敗し，非強制更新なので他者のコミットは上書きしません．トークンはブラウザの保存領域に保存しません．

### ZIPで手動公開する場合

書き出したZIPを展開し，`data/index.json` と `posts/YYYY-MM-DD.json` と新規 `images/` を，サイトの対応する位置へアップロードします．**記事一覧ファイルは書き出し時の内容なので，別の端末で更新した場合は古い記事を消さないよう確認**してください．既存記事の日付を変えた場合は同梱の `DELETE_OLD_FILE.txt` に従って旧記事JSONを削除してください．

### 検索とパフォーマンス

- トップページはまず `data/index.json` の小さな一覧だけを読み込みます．
- 通常表示は最初の6件の日別JSONだけを取得し，**もっと読む**で次の6件を取得します．
- 年・タグの絞り込みは一覧情報だけで動きます．
- **本文を含むキーワード検索**では日別JSONを順次取得します．検索時は記事数に応じて通信量が増えます（最大6件並列）．
- 写真は各記事の読み込み後に遅延読み込みされます．

## 注意

- 日別ファイルは**1日に1記事**です．同じ日に別の記事を公開しようとすると公開前にエラーになります．
- GitHub Pages上では，`editor.html` や `preview.html` の画面自体を他者が開くことは可能です．**閲覧制限・ログイン機能はありません．** 下書き自体はその人自身のブラウザ内にあり，他者には表示されません．
- 下書きはブラウザを替えたり保存領域を削除したりすると失われる場合があります．プレビューが働くのは編集と同じブラウザ・オリジンのときです．
- 写真は長辺最大1800pxで再エンコードします．公開時は写真に写り込む個人情報や位置情報を確認してください．
- `file://` でのダブルクリックはfetchが制限されるブラウザがあります．ローカル確認にはフォルダ内で `python3 -m http.server 8000` を起動し，`http://localhost:8000/editor.html` を開いてください．
- 旧版の `data/posts.json` 形式で既に公開した日記がある場合は，付属の `migrate_legacy.py` で日別ファイルへ変換できます．変換前にバックアップを取り，同じ日付の記事が重複しないことを確認してください．
